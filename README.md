# bon-app.net

The Bon App & T website. Static HTML generated by a small Python script, no framework
and no build dependencies beyond the standard library — served from this repository by
GitHub Pages.

Forked from [`euappsolutions.com`](https://github.com/TheEUAppSolutions/euappsolutions.com):
same generator, same design system, different brand and content.

## Why this exists

The old WordPress site returned **HTTP 500 for every URL**, and the company's legal pages
were scattered across domains it no longer controls:

| Domain | State when this was built (2026-09-20) | Cited by |
| --- | --- | --- |
| `bon-app.net` | whole WordPress install 500ing | Chooser! seller URL, Timestamp Camera privacy policy |
| `bonappt.co.uk` | **lost** — re-registered, now serves adult content; the cited paths 404 | Invoice Maker privacy + terms |
| `funky-monkey-apps.com` | does not resolve; parked on the registrar's `EXPIRE*` nameservers | AI Music seller URL, privacy + terms |
| `visionarystudio.app` | working | Chooser!, NoteSwift legal |

So this site hosts a privacy policy **and** terms for every app, on a domain the company
controls, at `/legal/<app>/privacy/` and `/legal/<app>/terms/`. Those are the URLs that
belong in App Store Connect.

## Layout

```
index.html  apps/  about/  contact/  legal/    generated — do not edit by hand
privacy-policy/  term-of-use/                  umbrella docs, text from the old site
legal/<app>/privacy/  legal/<app>/terms/       one pair per app, naming that app
assets/css  assets/js  assets/img              design system, generated imagery
src/
  apps.json          app data: curated copy + live App Store numbers
  legal-src/*.html   Wayback captures of the old pages (the live site was down)
  legal/*.html       cleaned fragments extracted from those captures
  build.py           generates every page
  make_apps_json.py  curated copy lives here; merges in live App Store metadata
  fetch_assets.py    downloads icons + screenshots, converts to webp
  make_social.py     og.png and apple-touch-icon.png
  check.py           post-build link/asset/SEO checks
  extract_legal.py   re-derives src/legal/ from the captures
```

## Rebuild

```bash
./build.sh              # refresh App Store data, fetch artwork, build, check
./build.sh --offline    # build from committed data, no network
python3 -m http.server 4174   # preview
```

## The legal text

Reproduced from Wayback Machine captures of bon-app.net, not rewritten — with two
deliberate substitutions, both handled as tokens so they are auditable:

- **`{{APP_NAME}}`** — the captured policy defines the "Application" as
  *"Car connect – My Smart keys"*, an app this company does not publish, copy-pasted when
  the policy was cloned. Each per-app page names its own app; the umbrella pages name all
  five.
- **`{{PRIVACY_URL}}` / `{{TERMS_URL}}`** — the captured terms link to
  `/bone-app-t-privacy-policy/` and `/bone-app-t-term-of-use/`, which were never captured
  by the archive and do not exist. They were broken on the old site too (a typo for
  `bon-app-t-`). They now point at the real pages.

> **These documents have not been reviewed by a lawyer.** They are the company's own
> existing boilerplate, restored and re-pointed. Read them before relying on them,
> particularly the sections naming data collected.

## Which apps appear

Only apps whose App Store `sellerName` is exactly `BON APP & T LTD`. That check is not
cosmetic: apps built on this Apple team ship under several different sellers, and
`com.funkymonkeyapps.AiAssistant` (AI Chatbot) belongs to a different seller entirely
despite sharing a bundle prefix with AI Music. A wrong bundle ID fails the build rather
than publishing someone else's app.

Edit copy in `CURATED` in `src/make_apps_json.py`. Ratings, prices, categories, artwork
and dates come from Apple — don't hand-edit those.

## Deploying

Repository: `TheEUAppSolutions/bonapp-website`, served by GitHub Pages.

Two branches, because the domain hasn't moved yet:

| Branch | Built with | Serves | Purpose |
| --- | --- | --- | --- |
| `main` | `./build.sh` (root paths, has `CNAME`) | `bon-app.net` | the real site, **after** the DNS cutover |
| `preview` | `python3 src/build.py --base /bonapp-website`, no `CNAME` | [theeuappsolutions.github.io/bonapp-website](https://theeuappsolutions.github.io/bonapp-website/) | reviewable today |

Pages currently points at `preview`. Two traps worth knowing:

- A root-path build under a project URL breaks: every asset is referenced as
  `/assets/...`, which resolves to `theeuappsolutions.github.io/assets/...` and 404s.
  That's what `--base` fixes.
- **Changing the Pages source does not trigger a build.** After switching branches, push
  a commit or run
  `gh api -X POST repos/TheEUAppSolutions/bonapp-website/pages/builds`, otherwise Pages
  keeps serving the previous branch's output and the change looks like it did nothing.
- Removing the custom domain in the Pages UI **commits a `CNAME` deletion** to the source
  branch. If that happens to `main`, rebuild to restore it.

Pages responses carry `cache-control: max-age=600`, so a browser can hold the old HTML
for ten minutes after a deploy. Hard-refresh before concluding something is broken.

### Updating the preview

```bash
git checkout preview && git merge main
python3 src/build.py --base /bonapp-website
rm -f CNAME && printf 'User-agent: *\nDisallow: /\n' > robots.txt
git commit -am "Refresh preview" && git push
```

### Cutover

Claim the domain on GitHub **before** moving DNS, or someone else can host on it in the
gap. `bon-app.net` is registered with **Hostinger** (nameservers `ns1`/`ns2.dns-parking.com`),
so DNS is edited in hPanel, not Squarespace.

1. Repo → Settings → Pages → Branch `main`, `/ (root)`. The `CNAME` file sets the domain.
2. Hostinger hPanel → Domains → bon-app.net → DNS / Nameservers → DNS records:

| Action | Name | Type | Value |
| --- | --- | --- | --- |
| **Delete** | `@` | A | `92.113.16.153` and `92.113.23.16` (old WordPress) |
| Add | `@` | A | `185.199.108.153` / `.109.153` / `.110.153` / `.111.153` |
| Add | `@` | AAAA | `2606:50c0:8000::153` / `:8001::153` / `:8002::153` / `:8003::153` |
| **Edit** | `www` | CNAME | point at `theeuappsolutions.github.io` |

   **Do not touch** the `MX` records (`mx1`/`mx2.hostinger.com` — email for info@) or any
   TXT/SPF record. `www` currently points at Hostinger's CDN, so edit it rather than
   deleting it.
3. Wait for `dig +short bon-app.net` to return the GitHub IPs, then for the certificate,
   then tick **Enforce HTTPS**.
4. Check `https://bon-app.net/privacy-policy/` returns 200 before cancelling Hostinger
   hosting — that URL is cited from a live App Store listing.

There is no outage risk in this cutover: the Hostinger site already returns HTTP 500 on
every URL.
