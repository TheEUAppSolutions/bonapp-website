# Bon App & T — euappsolutions.com/bonapp

The Bon App & T website, **hosted at [euappsolutions.com/bonapp/](https://euappsolutions.com/bonapp/)**.
Static HTML generated by a small Python script, no framework and no build dependencies
beyond the standard library.

This repo holds the source. The built site is written into the
[`euappsolutions.com`](https://github.com/TheEUAppSolutions/euappsolutions.com) repo under
`bonapp/`, and this repo's own root is a set of redirects that forward `bon-app.net` there
path for path.

Forked from [`euappsolutions.com`](https://github.com/TheEUAppSolutions/euappsolutions.com):
same generator, same design system, different brand and content.

## Why this exists

The old WordPress site returned **HTTP 500 for every URL**, and the company's legal pages
were scattered across domains it no longer controls:

| Domain | State when this was built (2026-09-20) | Cited by |
| --- | --- | --- |
| `bon-app.net` | whole WordPress install 500ing | Chooser! seller URL, Timestamp Camera privacy policy |
| `bonappt.co.uk` | **lost** — re-registered, now serves adult content; the cited paths 404 | Invoice Maker privacy + terms |
| `funky-monkey-apps.com` | does not resolve; parked on the registrar's `EXPIRE*` nameservers | AI Music seller URL, privacy + terms |
| `visionarystudio.app` | working | Chooser!, NoteSwift legal |

So this site hosts a privacy policy **and** terms for every app at
`/legal/<app>/privacy/` and `/legal/<app>/terms/`, and lives on euappsolutions.com rather
than a domain of its own: every failure above was a domain that lapsed or went unwatched,
and one domain is easier to keep alive than four. The policies still name
**Bon App & T Ltd** as the company, which is what Apple checks.

The trade-off is portability. If Bon App & T or one of its apps is sold, its policy URLs
sit on a domain the buyer doesn't control. Moving it back out is a one-flag change
(`--mount https://bon-app.net`), but the App Store Connect URLs would need updating.

## Layout

```
index.html  apps/  about/  contact/  legal/    generated — do not edit by hand
privacy-policy/  term-of-use/                  umbrella docs, text from the old site
legal/<app>/privacy/  legal/<app>/terms/       one pair per app, naming that app
assets/css  assets/js  assets/img              design system, generated imagery
src/
  apps.json          app data: curated copy + live App Store numbers
  legal-src/*.html   Wayback captures of the old pages (the live site was down)
  legal/*.html       cleaned fragments extracted from those captures
  build.py           generates every page
  make_apps_json.py  curated copy lives here; merges in live App Store metadata
  fetch_assets.py    downloads icons + screenshots, converts to webp
  make_social.py     og.png and apple-touch-icon.png
  check.py           post-build link/asset/SEO checks
  extract_legal.py   re-derives src/legal/ from the captures
```

## Rebuild

Needs the `euappsolutions.com` repo checked out next to this one (`../euappsolutions-site`,
or set `EU_SITE`).

```bash
./build.sh              # refresh App Store data, fetch artwork, build, check
./build.sh --offline    # build from committed data, no network
```

That writes the site into `../euappsolutions-site/bonapp/`, checks it there, then
regenerates the redirects at this repo's root. **Commit in both repos** afterwards —
the euappsolutions one is what actually publishes.

`src/build.py` modes, for reference:

| Flag | Output | Canonical URLs |
| --- | --- | --- |
| `--mount https://euappsolutions.com/bonapp --out DIR` | the real site | `euappsolutions.com/bonapp/...` |
| `--redirect-to https://euappsolutions.com/bonapp` | redirect stubs at repo root | — |
| *(none)* | standalone site at repo root | `bon-app.net/...` |
| `--base /x` | github.io project-URL preview | `bon-app.net/...` |

## The legal text

Reproduced from Wayback Machine captures of bon-app.net, not rewritten — with two
deliberate substitutions, both handled as tokens so they are auditable:

- **`{{APP_NAME}}`** — the captured policy defines the "Application" as
  *"Car connect – My Smart keys"*, an app this company does not publish, copy-pasted when
  the policy was cloned. Each per-app page names its own app; the umbrella pages name all
  five.
- **`{{PRIVACY_URL}}` / `{{TERMS_URL}}`** — the captured terms link to
  `/bone-app-t-privacy-policy/` and `/bone-app-t-term-of-use/`, which were never captured
  by the archive and do not exist. They were broken on the old site too (a typo for
  `bon-app-t-`). They now point at the real pages.

> **These documents have not been reviewed by a lawyer.** They are the company's own
> existing boilerplate, restored and re-pointed. Read them before relying on them,
> particularly the sections naming data collected.

## Which apps appear

Only apps whose App Store `sellerName` is exactly `BON APP & T LTD`. That check is not
cosmetic: apps built on this Apple team ship under several different sellers, and
`com.funkymonkeyapps.AiAssistant` (AI Chatbot) belongs to a different seller entirely
despite sharing a bundle prefix with AI Music. A wrong bundle ID fails the build rather
than publishing someone else's app.

Edit copy in `CURATED` in `src/make_apps_json.py`. Ratings, prices, categories, artwork
and dates come from Apple — don't hand-edit those.

## bon-app.net

Keep it — and keep renewing it. Chooser! (39k ratings) lists it as its seller URL and
Timestamp Camera's current privacy policy is `bon-app.net/privacy-policy/`. Letting it
lapse is how bonappt.co.uk ended up serving porn.

This repo serves it as a redirector on GitHub Pages (`CNAME` = `bon-app.net`, Pages source
`main`). GitHub Pages can't send 301s, so each known path is a meta-refresh + JS stub, and
`404.html` forwards any other path unchanged — `bon-app.net/anything` lands on
`euappsolutions.com/bonapp/anything`.

It only takes effect once DNS moves off Hostinger's broken WordPress. Claim the domain on
GitHub first (Pages source `main` with the `CNAME` file), then in **Hostinger hPanel →
Domains → bon-app.net → DNS**:

| Action | Name | Type | Value |
| --- | --- | --- | --- |
| **Delete** | `@` | A | `92.113.16.153` and `92.113.23.16` (old WordPress) |
| Add | `@` | A | `185.199.108.153` / `.109.153` / `.110.153` / `.111.153` |
| Add | `@` | AAAA | `2606:50c0:8000::153` / `:8001::153` / `:8002::153` / `:8003::153` |
| **Edit** | `www` | CNAME | point at `theeuappsolutions.github.io` |

**Do not touch** the `MX` records (`mx1`/`mx2.hostinger.com` — email for info@bon-app.net)
or any TXT/SPF record. `www` currently points at Hostinger's CDN, so edit it rather than
deleting it. No outage risk: the Hostinger site already returns HTTP 500 on every URL.

Then tick **Enforce HTTPS** once the certificate issues, and check
`https://bon-app.net/privacy-policy/` lands on the euappsolutions.com copy before
cancelling the Hostinger hosting.

### GitHub Pages traps met along the way

- A root-path build under a project URL breaks: assets referenced as `/assets/...` resolve
  to `theeuappsolutions.github.io/assets/...` and 404.
- **Changing the Pages source does not trigger a build.** Push a commit or run
  `gh api -X POST repos/TheEUAppSolutions/bonapp-website/pages/builds`.
- Removing the custom domain in the Pages UI **commits a `CNAME` deletion** to the source
  branch.
- Pages sends `cache-control: max-age=600`; hard-refresh before concluding a deploy failed.

The `preview` branch (a `--base /bonapp-website` build) predates the move to
euappsolutions.com and is no longer used.
